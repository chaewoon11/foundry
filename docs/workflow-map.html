3. A briefing

The same shape in stages 1, 2 and 5. Decisions are recorded at once in a REVIEW.md file next to the documents.

Page

Big picture as an HTML page: conventions, problem, algorithm, code structure, verification map, scope, decisions. No approval.

Check

"Anything odd or missing in this picture?"

User's questions

Only questions with no correct answer: purpose, scope, API, trade-offs, the level. One per message.

Agent decisions

Derivable choices (formulas, derived tolerances, conventions) as one list; veto any line.

Approve

Changes re-briefed, then the whole review approved. A hook refuses while anything is open.

4. The pieces behind it

Hooks

guard: the table above, per role and per code. review gate: no approval with open items; agents cannot write decisions; no shell edits of REVIEW.md. session start: status and orchestrator rules in every new session.

Verification levels

L1 analytic + transformation tests, no holdout, no oracle, no mutation. L2 + consistency and order or oracle, some holdout, mutation on key terms ≥ 70 %. L3 everything, ≥ 90 %.

Test kinds

① analytic · ② transformations · ③ two routes, same answer · ④ convergence order · ⑤ oracle / manufactured · ⑥ community data. Rules, not hand-picked cases.

Resuming

No state file: the stage is read from the files. "Let's continue" in a new session picks up where the run stopped; agents keep progress notes.
